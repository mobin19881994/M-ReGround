Recent Changes (Applied)
========================
- Project rename:
  - Display name and product strings changed to "M-ReGround".
  - Dart package name changed to `m_reground` and imports updated across source files.

- Demo / Local-only mode:
  - `--dart-define=MREGROUND_USE_LOCAL_ONLY=true` runs the app without Firebase and enables simulated auth/data.
  - Added `lib/core/services/demo_data_service.dart` with seeding, list, apply, and clear helpers.
  - Auto-seeding behavior: demo data is auto-seeded when `demo_accounts` are missing or when `demo_auto_seed` is true; `seedNow()` force-seeds.
  - `--dart-define=MREGROUND_FULL_DEMO=true` (test-only) sets `demo_auto_seed=true`, `demo_ignore_locks=true`, and activates `demoCustomerEmail` as active on startup.

- Demo UX & profile controls:
  - `lib/features/debug/demo_profiles_screen.dart`: UI to view/apply demo profiles.
  - `lib/features/profile/profile_screen.dart`: toggles added: `Auto-seed demo on startup` and `Ignore locks for demo user` (persisted as `demo_ignore_locks`).
  - `lib/widgets/demo_banner.dart`: banner explains demo behavior.


- Timer & lock behavior:
  - `lib/core/services/foreground_timer_service.dart`:
    - `defaultTimeSlotsInMinutes` now includes short slots (1,2,3) to support quick demo testing (also accessible to demo users via helper).
    - Demo-ignore-locks respected in `isLevel4Locked` (reads `demo_ignore_locks` from storage).
    - When a break task is completed, `completeTaskAndResetToLevel1()` now clears `dailyUsageMinutes` and any level-4 lock so the user returns to Level 1.
    - Timer lifecycle, persistence, and `_taskGateOpen` behavior preserved; overlay gating updated so demo users also see break-task overlays.

- Tasks & Task engine:
  - `lib/core/models/task_model.dart`: `BreakTask` has explicit `id` field for tracking.
  - `lib/core/services/task_engine_service.dart`: full set of tasks for Level 1..4 added with stable `id` values (e.g. `l1_smile`, `l2_drink_water`, `l4_cooldown`).
  - `lib/features/tasks/task_selection_overlay.dart` converted to a stateful widget with a Start/Complete flow: user must press `Start Task` before `Complete Task` is enabled; Lottie visuals still used.

- Permissions & native integration:
  - `lib/main.dart` requests runtime permissions at startup (Camera, ActivityRecognition) using `permission_handler` and calls `NativeInterceptionService.requestOverlayPermission()` to ask for overlay permissions via the native bridge.
  - If Camera or ActivityRecognition permission is permanently denied, the app now opens app settings to prompt the user to enable them.
  - Native channel names updated in Android/iOS stubs to `m_reground/native_interception` and `m_reground/native_overlay`.

- Build & CI:
  - A full-demo release APK was built for testing at `build/app/outputs/flutter-apk/app-release.apk` using:
    - `--dart-define=MREGROUND_USE_LOCAL_ONLY=true`
    - `--dart-define=MREGROUND_FULL_DEMO=true`
    - `--dart-define=MREGROUND_ALLOW_BYPASS_IN_RELEASE=true`
  - CI SCA workflow added: `.github/workflows/sca.yml` runs OWASP dependency-check and uploads reports as artifacts.

- Tests & verification:
  - `flutter analyze` and `flutter test` passed after edits; widget tests covering demo UI were added.
  - Manual verification steps (recommended): seed demo data (Profile → Seed Demo Data), start a 1-minute allowance, wait for expiry, start and complete a break task; verify level resets and demo-ignore-locks behavior.

2) Foreground Session Timer + Overlay

- When timer reaches 0, show break task overlay.

3) Break Task Engine (Dual Choice + fallback)
- Build task engine with TaskType {camera, sensor, mindful} and TaskLevel {1..4}.
- Adaptive task choices must include camera/sensor/mindful options.
- If camera denied or low light, auto-prioritize non-camera options.
- Use local Lottie assets only (no remote URLs).

  - assets/animations/sensor_task.json
  - assets/animations/mindful_task.json
